# Пункты 4–5: streaming, восстановление запросов и Mastra

Реализованы пункты пользовательского плана «настоящий streaming» и «перенос на Mastra»
(разделы 8–9 в [подробном плане](agent-platform-implementation-plan.ru.md)).

## Что работает

- Защищённый HTTP transport возвращает поток сразу после заголовков. DNS проверяется и
  закрепляется за сокетом; перенаправления не выполняются. Сжатые и распакованные данные
  ограничены отдельно, по 2 MiB; сохраняются backpressure и ошибка после заголовков.
- Отдельные ограничения соединения (10 с), первого ответа и простоя (30 с), общий
  timeout профиля и верхний предел запроса 120 с. Меньший timeout профиля имеет приоритет.
- OpenAI-compatible SSE, Anthropic messages SSE и Gemini streamGenerateContent SSE:
  разбор UTF-8 через границы чанков, ограничение кадра, сборка аргументов инструмента,
  terminal marker и usage. Обычный JSON-ответ остаётся совместимым fallback, без
  обещания ранних токенов. Частичный JSON никогда не передаётся на запись.
- В SQLite истории добавлены отдельные `run_snapshots` и `run_events`. Старые таблицы
  и формат `chat_runs` сохранены. WAL с `synchronous=FULL`; критическое событие
  фиксируется до доставки. Дельты объединяются по 80 мс / 1024 символа.
- Сохраняются `run.accepted`, `run.started`, привязка версии профиля `run.bound`,
  `text.delta`, `tool.started/completed/failed`, `artifact.saved`, терминальный результат.
  У каждого события устойчивый sequence; после финала новые события не принимаются.
- WebSocket `resume` принимает `chatId`, `requestId`, `lastSequence`. Возвращается хвост
  последних 512 событий или полный snapshot с курсором. REST статуса читает тот же
  snapshot. Повтор отправленного requestId сохраняет прежнюю защиту от повторных записей.
- PWA выводит частичный Markdown, обнаруживает пропуски, отбрасывает дубли, заменяет
  черновик финальным ответом. При восстановлении страницы доступен polling snapshot.
  Прокрутка следует ответу, пока пользователь не ушёл читать предыдущие сообщения.
- Отключение WebSocket не отменяет запрос. Отмена остаётся отдельным действием.
  После restart незавершённый run отмечается interrupted с известными артефактами;
  модель автоматически повторно не запускается. Сохранённый перед сбоем финал
  восстанавливается из `chat_runs`. Восстановление мутаций выполняется перед аудитом runs.
- События и snapshot удаляются при очистке чата и по тому же 14-дневному TTL.
  Долговременный tombstone запроса не получает текст сообщения или потока.

## Рабочий движок

По умолчанию заметки исполняются через закреплённый `@mastra/core@1.78.0`.
Mastra и схема инструментов теперь являются production-зависимостями сервера.
Общий `AgentLoop` позволяет выбрать прежний движок для новых запросов:

```dotenv
AGENT_ENGINE=mastra
AGENT_MAX_STEPS=4
```

Для отката — `AGENT_ENGINE=legacy` и перезапуск сервера. Движок уже принятого запроса
не меняется; оба варианта используют одни доменные обработчики и события. Автоматического
повтора того же запроса через другой движок нет.

Mastra работает внутри существующего Fastify API. Её модельный адаптер вызывает
`ProviderRegistry` / `LlmClient`, сохраняя снимок профиля, версии ключа, modelId и
защищённый transport. SDK не выбирает глобальные ключи из ENV. Встроенные подробные
логи SDK отключены: они могут включать содержимое инструментов. Приложение сохраняет
свои числовые метрики, включая время первого текста; Mastra instance закрывается
после запроса. Mastra Memory и дополнительное хранилище SDK не включены.

Единые определения инструментов и `ToolSpec` задают доступность, схему, класс чтения /
записи, предел чтения 10 с и результата 16 000 символов. Два независимых чтения могут
выполняться одновременно; записи образуют последовательный барьер. Запись не гоняется
с таймером и не повторяется автоматически. Ошибка после сохранения возвращает partial
и список сохранённых заметок.

Добавлен `read_section(path, chunkId)`: идентификатор берётся из поиска, раздел
перечитывается из актуального Markdown с contentHash и смещениями. Чтение раздела
не разрешает полную замену заметки. `update_note` по-прежнему требует полного чтения
и точного хеша; реальные изменения проходят через `NoteModeService` и мутации vault.

Контекст ограничен: свежая история — до 24 000 символов, summary — до 8 000,
фрагменты явно выбранных текущих вложений — до 24 000. Ранжирование по запросу
ограничено первыми 200 000 символов файла; Markdown учитывает границы разделов.
`read_attachment(fileId, offset, limit)` позволяет дочитать любой диапазон всего
извлечённого текста, максимум 8000 символов за вызов, с проверкой выбора файла,
устройства, чата и TTL. Модель видит смещения и признак неполного чтения.
Без поддержки tools доступны только выбранные фрагменты. Прошлые вложения больше не
добавляются автоматически; для нового обращения к файлу его нужно выбрать заново.
Инструменты возвращают ограниченные фрагменты. Бюджет — 4 модельных шага, максимум
6 через конфигурацию, включая последний шаг без инструментов; до 4096 выходных
токенов за шаг и суммарно 48 000 учтённых/оценённых токенов. Если API не прислал usage,
используется приближённая оценка по символам, а не обещание точной денежной стоимости.
Повторы SDK отключены; сбой не повторяет уже выполненную мутацию.

`/quick`, `/idea`, `/person` сохраняют быстрый путь без модели. Режим задач остаётся
ограниченным извлечением JSON, проверкой срока и вызовом `TaskService`; сырой JSON
не выводится в поток. Срок принимается только из пользовательских реплик: дата в
содержимом вложения не считается явно указанным пользователем сроком.

## Проверки

- `npm test`: 33 core + 100 server = **133 прошедших теста**.
- `npm run typecheck` и `npm run build`: core, server и PWA.
- `npm run check:compatibility`: реальный локальный HTTP, SDK text/tool/stream/error/
  abort и импорт assistant-ui с React 18; `transportStreaming: true` в
  [отчёте](agent-compatibility.json).
- `node benchmarks/production-runtime.mjs`: отдельная установка
  `npm ci --omit=dev --ignore-scripts --offline`, health, авторизованный запрос
  через Mastra, SQLite snapshot, повтор того же requestId и быстрая запись без
  дополнительного модельного вызова. [Отчёт](production-runtime-smoke.json).
- Тесты обоих движков проверяют текст до завершения потока, source hashes,
  проверку инструментов до записи, partial после записи и отмену с закрытием
  сокета. Проверены reconnect, отсутствие второго provider call, batching,
  compaction, restart, очистка и TTL. Нативные адаптеры проверены на SSE-фикстурах,
  включая подпись Gemini и оборванный ответ.

Проверка `npm audit --omit=dev`: **0 high / critical**, 5 moderate в транзитивной
цепочке Mastra → gray-matter → js-yaml → argparse → sprintf-js и 3 low в цепочке
remark-math / KaTeX. Для sprintf-js реестр пока не предлагает исправленную версию;
предлагаемый audit downgrade Mastra не применялся. Парсер приложения использует `yaml`,
а не этот gray-matter. Это не означает отсутствия риска в установленной зависимости.

Внешние платные модели, мобильный браузер, Docker и VPS в этой проверке не запускались.
Ранний вывод подтверждён локальными детерминированными потоками; ускорение самой LLM
и экономия стоимости на реальном провайдере здесь не измерялись.
