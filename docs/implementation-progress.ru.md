## Контракты текущего API

Создание принимает `{ operationId, task: TaskCreateInput }`. Обновление принимает
`{ operationId, expectedContentHash, patch: TaskPatch }`. Запись возвращает
`{ task, receipt }`, где receipt различает `saved_local`, `committed`, `synced`.
Одинаковый operationId разрешён только для того же тела запроса.

Ошибки: 422 — некорректные данные/срок, 409 — устаревшая версия или повтор ID с другим
запросом, 401 — отсутствующий/неподходящий ключ, 500 — ошибка выполнения с возможностью
повторить запрос с прежним operationId. Для ручной задачи отсутствующий срок сразу
отклоняется; диалоговое уточнение срока ИИ позднее реализовано в режиме задач.

## Проверено

- `npm test`: 27 тестов — 13 core и 14 server, все прошли.
- `npm run typecheck`: все три пакета прошли проверку.
- Полная production-сборка окончательных изменений прошла.
- Проверены повторные и конкурентные запросы, отсутствие срока, устаревший hash,
  сохранение неизвестного YAML, смена вида срока, точная граница TTL и миграция.
- Проверены сбои после rename до коммита и после коммита до обновления журнала,
  сохранение поздней правки, точное сопоставление ID операции и исключение чужого staged-файла.
- Через локальный bare Git remote проверены отказ публикации, сохранность локальной задачи,
  последующий успешный push и состояние `synced`.
- Проверен выход за пределы vault через Windows junction.
- В браузере на размере 390×844 проверены вход, сохранение черновика при смене области,
  переход в настройки без потери черновика, ручное создание задачи, категория, приоритет,
  завершение и фильтр «Готовые». После обновления PWA повторно проверен рабочий экран.
  Стенд использует отдельное тестовое хранилище `data/development-preview`, `SYNC_MODE=none`.
  Реальные пользовательские заметки, модели и SMS в этих сценариях не использовались.
  Снимок: `data/development-preview/screenshots/tasks-mobile.jpg` (локальный артефакт,
  не добавляется в Git).
- Проверены 404 для отсутствующих assets, SPA-fallback `/share` и появление нового
  JavaScript-файла без перезапуска сервера.

OpenCode запускался через CLI с `openai/gpt-6.1-sol`, вариантом `high` и агентом `plan`.
Независимая исследовательская задача не передавала исходники: риски согласованности SQLite,
Markdown и Git при повторах и сбоях. Полученные пять рисков проверены по реализации и
сценариям восстановления; изменений файлов OpenCode не выполнял.
Ревью исходников через OpenCode пока не выполнено: автоматическая проверка разрешений
отклонила передачу файлов внешнему сервису, запрос на разрешение остаётся открытым.

## Завершение оставшихся этапов

Нативные API-провайдеры и ротация ключа, несколько задач и редактирование через ИИ,
индекс и backfill ID, восстановимая OCR-очередь, календарь и канбан, сортировщик,
веб-уведомления, tickets WebSocket, восстановление запросов и редактор Git-конфликтов
реализованы. SMS заменены веб-уведомлениями по уточнению пользователя.

Итоговая матрица этапов, новые контракты, обработка ошибок, результаты проверок и
инструкция эксплуатации: [completion-2026-10-03.ru.md](completion-2026-10-03.ru.md).
Подключение реальных моделей, Git-сервера и проверка push на телефоне требуют
настроек владельца; тесты используют отдельное хранилище и локальные адаптеры.

Один сервер владеет записью в vault; повторный экземпляр блокируется. При
`SYNC_MODE=none` данные сохраняются без Git-коммита. Пакетный журнал восстанавливает
многофайловые операции, но не создаёт общей транзакции для внешнего Obsidian.

История исключается из долгосрочных backup настройками эксплуатации: автоматической
очистки существующих внешних backup нет. Приложение не может удалить журналы и записи,
хранящиеся у внешнего AI-провайдера.
