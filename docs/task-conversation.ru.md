# Диалоговый режим задач

Режим передаёт последние 24 реплики, текущий черновик и каталог существующих задач. В состоянии чата сохраняются ID последнего результата и его серии. Ссылки «эту», «последнюю», «вторую», «эти задачи» разрешаются по этим ID с проверкой актуального состояния. ID и правило серии переживают перезапуск. Контекст изолирован по устройству и чату, очищается с историей и ограничен её сроком хранения. Для старых чатов ссылки восстанавливаются по сохранённым действиям ассистента.

## Операции

| Запрос | Операция |
| --- | --- |
| «Сдать ДЗ 24 октября в 23:59» | `create` — одна задача |
| «Отчёт до пятницы и встреча завтра в 18:00» | `create` — несколько задач с разными сроками |
| «Каждую субботу с 24 октября в 23:59, всего 6» | `series` — конечная серия с первой датой включительно |
| «После 24 октября ещё 6 раз каждую субботу» | `series` с `includeStart:false`, либо `extend` для существующей задачи |
| «Такие же ещё 6» | `extend` — шесть новых задач после конца серии, время и правило наследуются |
| «Продолжай до 31 декабря» | `extend` с включительной конечной датой |
| «Скопируй последнюю на завтра» | `duplicate` — копия со статусом `todo`, без принадлежности к старой серии |
| «Вторую перенеси на 31 октября в 18:00» | `update` — изменить конкретный срок |
| «Эти задачи на неделю позже» | `shift` — сдвинуть выбранные сроки |
| «Всю серию на неделю позже» | `shift` — сдвинуть и сроки, и общую календарную основу серии |
| «Первую заверши, вторую переименуй» | `update_many` — разные изменения одним пакетом |
| «Отмени все оставшиеся в серии» | `update` с `target.kind:series`, `scope:pending`, `status:cancelled` |
| «Верни последнюю в работу» | `update` со статусом `todo` или `in_progress` |
| «Что просрочено?», «Покажи учебные задачи за ноябрь» | `list` — фильтры по периоду, категории, статусу и просрочке |
| «Отмени черновик», `/cancel` | `cancel_draft` — отменить незавершённый запрос |

При неоднозначном названии сервер возвращает варианты с кодами и сроками. Недоступная ссылка не заменяется произвольной другой задачей. Список можно читать без записи файлов. Новый самостоятельный запрос не наследует срок предыдущей задачи; наследование разрешено для копирования и продолжения выбранной задачи/серии. Завершение, восстановление, отмена, название, описание, приоритет, категория и метки используют общий валидатор задач. Отмена меняет статус, файлы сохраняются.
Явно множественные запросы («все учебные задачи октября», «все просроченные») используют `target.kind:filter`. Сервер применяет фильтр к актуальному списку задач; пустой фильтр для изменения не допускается.

## Правило серии

Серия представлена `TaskSeries`: стабильный `id`, номер `index` с нуля, исходный срок `anchor` и `recurrence`. Метаданные `task_series` хранятся во frontmatter каждой задачи; SQLite остаётся проекцией Markdown. Ручные обычные патчи не могут менять принадлежность к серии.

Поддерживаются `daily`, `weekly`, `monthly`, `yearly` с положительным интервалом и выбранными днями недели для `weekly` (1 — понедельник, 7 — воскресенье). Календарь разворачивает сервер. Требуется количество новых задач или конечная дата включительно. Количество всегда означает число создаваемых сроков после учёта `includeStart`. Лимит — 100 задач за запрос, без молчаливого обрезания.

Даты рассчитываются в часовом поясе исходного срока с сохранением местного времени. Для ежемесячных/ежегодных повторений используется день исходной даты: 31 января → 28 февраля → 31 марта. В месяце без нужного дня выбирается последний день. Невозможное или двойное местное время при переходе часов требует уточнения до записи всего пакета.

Изменение срока отдельного повторения — исключение: продолжение идёт по исходному правилу с номера после последнего сохранённого повторения. Сдвиг всей серии переносит и её основу. Для недельного правила с явно заданными днями поддерживается общий сдвиг на целое число недель; иной сдвиг требует уточнения расписания. Продолжение обычной задачи включает исходную задачу в серию вместе с новыми повторениями одной операцией.

Бесконечные серии, праздничные календари и правила вроде «последняя пятница месяца» не подменяются приблизительными датами: агент должен объяснить ограничение и уточнить конечное поддерживаемое расписание. Смешанный запрос на создание и изменение разбивается уточнением; разные изменения существующих задач поддерживает `update_many`.

## Черновики, ошибки и подтверждения

Если не хватает срока или границы серии, сохраняется полная незавершённая операция вместе с известными полями и пользовательскими цитатами/временем реплик. При уточнении относительная дата относится к исходной реплике, даже если она вышла из окна последних сообщений. Вложения и ответы ассистента не считаются пользовательским подтверждением срока.

JSON модели проходит проверку до записи. При неверной структуре даётся одна попытка исправить ответ; затем возвращается понятная ошибка «Ничего не записано», с машинным кодом `TASK_MODEL_OUTPUT_INVALID` в результате и метаданных сообщения. Необработанное «Ожидается объект» пользователю не показывается. Контракт совместим со старой схемой одиночных задач и `multiple`.

Создание и разные изменения сохраняются пакетами с проверкой всех версий, текущего режима и отмены запроса. Повторная отправка того же requestId возвращает прежний результат. Повторное создание того же названия/категории/срока сообщает об уже существующей задаче; явное копирование разрешает дубликат. Одинаковые существующие задачи можно связать в серию без повторного создания.

Подтверждение строит сервер по реально сохранённым задачам: количество созданных/существующих/изменённых, пронумерованные названия, все даты, время, часовой пояс и статус задачи. Каждая квитанция содержит путь и хеш собственного файла. Различаются локальная запись, Git-коммит и отправка в Git. При частичном сбое действует журнал сохранённых артефактов сервера: результат не скрывает уже записанные файлы.
При сбое задачи дополнительно проверяется совпадение фактических файлов с запланированными хешами: подготовленный, но ещё не записанный файл не объявляется сохранённым. Квитанции пакета задач свёрнуты в раскрываемый список, чтобы не заслонять основной результат.

## Проверка

`packages/server/test/task-conversation.test.ts` проверяет календарь, диалог из исходного обращения, продолжение серии, уточнения, ссылки на предыдущие результаты, разные изменения, состояния задач, неоднозначность, обработку неправильного JSON, переходы времени, конфликты версий, перезапуск/очистку контекста и HTTP-повтор запроса. HTTP-тест использует локальный имитатор провайдера и проверяет фактически переданные сообщения. Это проверка приложения и его контракта; качество извлечения намерения конкретной внешней моделью требует отдельной проверки на выбранном профиле.
