# Пункты 6–8: память, ход работы и документы

Реализация относится к пунктам 6–8 краткого плана: разделам 10–12
[подробного плана](agent-platform-implementation-plan.ru.md). Langfuse, MCP и
векторный поиск остаются отдельными последующими этапами.

## 6. Долговременные предпочтения

Постоянный источник — `System/Assistant/preferences.md` внутри vault. Файл имеет
метаданные `assistant_preferences: 1` и три раздела: «Общение», «Хранилище»,
«Рабочие правила». Размер ограничен 16 КиБ, отдельный раздел — 4000 символами.
Файл читается заново перед запросом, следует ограничениям доступа vault и исключён
из обычного поиска и автоматической сортировки.

В PWA кнопка «Память» открывает краткосрочное резюме чата и редактор постоянных
правил. Сохранение использует expectedHash и operationId. Если файл изменили в
Obsidian, существующий текст остаётся на месте, а кандидат пользователя сохраняется
как отдельный черновик конфликта на 14 дней с доступом только своему устройству.
Редактор показывает обе версии; повторное сохранение требует явной сверки.

Явные `/remember Текст правила` и «запомни, что …» сохраняют буквальный текст без
LLM. Эта команда принимается в режиме заметок без вложений. Модель, поиск и
содержимое PDF не могут записать этот файл через обычные инструменты заметок.
История, резюме и статусы задач не переносятся в постоянную память автоматически.
Сохранённые правила передаются как пользовательский контекст; текущий запрос,
правила приложения, доступ и строгая проверка сроков имеют приоритет.

Удаление правил сразу действует на следующий запрос и не зависит от удаления
чата. Повреждённая схема, превышенный размер и отозванный доступ дают предупреждение
и безопасную базовую конфигурацию без устаревшего кеша. Файл больше 16 КиБ нужно
сначала сократить в Obsidian; приложение не загружает его целиком для редактирования.

## 7. Понятный ход работы

Карточки показывают действие, состояние, длительность, короткий результат и
источники. Записи отдельно показывают подтверждённый путь и статус receipt:
локальное сохранение, commit, sync или конфликт. Статус отражает подтверждение
конкретной операции, а не обещает последующую синхронизацию. Ключи, полные аргументы
инструментов и текст документов в карточки не попадают.

Один reducer используется серверным RunSnapshot и клиентом: sequence защищает
от повторов, разрыв запрашивает восстановление, итог заменяет черновик текста.
Завершённые карточки и receipts сохраняются в истории. При отмене или прерывании
подтверждённая запись остаётся успешной; незавершённые действия получают отдельный
исход. Частичный ответ перечисляет уже выполненное и не предлагает повторить все
записи новым запросом.

Вложения, черновик и прокрутка сохраняются при переключении экранов; локальное
состояние вложений имеет исходный срок истечения. Долгое ожидание показывает
предупреждение и продолжает проверять принятый run. Добавлены доступные раскрываемые
карточки, области статуса, стабильные имена полей и закрытие PDF-окна по Escape.
Таблицы Markdown и блоки кода прокручиваются внутри ответа. Использован паттерн
ToolCall с собственными компонентами на текущем React 18; весь runtime assistant-ui
не подменяет существующий backend.

## 8. Документы и схемы

Сохранены локальные PDF.js, Tesseract rus/eng, DOCX и текстовые маршруты. PDF-страницы
разделяются на текстовые, сканы и страницы с графикой. Наличие текстового слоя
больше не выдаётся за понимание схемы. Исходный текст/OCR, предупреждения и
интерпретация модели хранятся отдельно, с номером страницы, версией обработчика,
хешем файла, моделью и версией профиля.

Для готового PDF кнопка «Схемы» открывает выбор страниц и вопрос. Пользователь явно
запускает отдельную фоновую обработку до девяти страниц, пакетами до трёх:

- Если профиль явно поддерживает native PDF, `pdf-lib` создаёт PDF только выбранных
  страниц. OpenAI-compatible/OpenRouter, Anthropic и Gemini получают свой формат
  PDF-вложения. Для OpenRouter явно указан native engine без скрытого перехода
  на платный OCR.
- В остальных случаях профиль должен поддерживать изображения: выбранные страницы
  рендерятся PDF.js в JPEG. Одного флага vision недостаточно для native PDF.
- Модель возвращает проверенный JSON с точным набором номеров исходных страниц.
  Инструменты и запись предпочтений в этом запросе отсутствуют. Обычный чат читает
  сохранённые фрагменты/страницы через ограниченный `read_attachment`, а не повторно
  отправляет весь документ.

Работают кеши локального извлечения и модельного объяснения по устройству/чату,
содержимому, версиям и настройкам. Временные производные удаляются с историей/TTL.
Успешные пакеты переживают ошибку следующего пакета; новый запрос с тем же вопросом
и профилем отправляет только недостающие страницы. Явный импорт сохраняет оригинал,
текст, отдельные объяснения модели и provenance в постоянном vault.

Обработка идёт в существующей очереди с fencing. Очередь разбора ограничена восемью
активными заданиями устройства и 64 общими; локальное распознавание имеет такую же
отдельную квоту. OCR/рендер исполняются в дочерних процессах. Отмена, удаление истории,
TTL и отзыв устройства останавливают работу и запрещают позднюю запись. После
перезапуска сохранённый недоставленный intent восстанавливается; ранее отправленный
модельный запрос получает unknown без автоматического платного повтора.

Ограничения сохранены согласованно: загрузка до 5 МиБ, PDF до 100 страниц, общий
разбор до 180 с, подготовка пакета до 40 с, JPEG до 4 млн пикселей на страницу,
пакет до 5 МиБ и ограниченный ответ модели. Кеш — до 2 МиБ на запись и 10 МиБ
на устройство. Лимит загрузки не повышен отдельно от parser, BLOB, base64, transport
и ресурсов сервера. Большие оригиналы пока нужно разделять; потоковое хранилище
крупных файлов и полноценный порт MarkItDown не входят в этот выпуск.

## Выполненные проверки

- `npm test`: **37 core + 118 server = 155 прошедших тестов**. Включены реальные
  локальные HTTP-запросы, SDK, PDF/OCR-процессы, CAS, кеш, partial, отмена,
  очистка во время запроса, восстановление очереди и изоляция устройств.
- `npm run typecheck` и `npm run build`: core, server, PWA.
- [Браузерная проверка](agent-ui-stage-6-8.json): Chrome headless, 320/390/1440 px,
  таблица, длинный путь, клавиатура, reduced motion, потеря WS, отсутствие дублей,
  сохранение/конфликт правил, загрузка и разбор PDF, сохранность черновика/вложений.
  Ошибок JavaScript и горизонтального переполнения страницы не обнаружено.
- [Рабочая установка](production-runtime-smoke.json): отдельный
  `npm ci --omit=dev --ignore-scripts --offline`, запуск сервера, авторизованный
  Mastra-запрос, replay, правила create/read/delete, локальное извлечение PDF,
  выделение страниц и рендер JPEG без dev-зависимостей.
- Исправлена выявленная тестами гонка транспортного потока при отмене тела HTTP
  ошибки. Отдельный тест проверяет закрытие восьми продолжающихся ответов 503;
  ограничения размера, gzip/SSE и поздние ошибки остаются проверенными.

Воспроизведение браузерного сценария: `node benchmarks/agent-ui.mjs` при доступном
Playwright. Необязательный первый аргумент — каталог node_modules с Playwright.
Используется изолированный синтетический vault и локальный HTTP-провайдер; скриншоты
попадают в игнорируемый `data/agent-ui-screens/`. Рабочая установка:
`node benchmarks/production-runtime.mjs` после сборки и заполнения npm-кеша.

Платная внешняя модель, физический телефон, чтение настоящим screen reader,
Docker и VPS не проверялись. Ключей провайдера в локальной конфигурации нет.
Реальное качество понимания учебных схем и нагрузку на VPS нужно проверить перед
выпуском; локальные фикстуры подтверждают маршрутизацию и сохранность данных.
Эти проверки не являются измерением ускорения внешней LLM.

Миграции добавляют таблицы краткосрочного кеша/заданий/конфликтов; существующие
Markdown и историю не заменяют. Для отката сохраняются vault и обе SQLite с WAL;
временные производные можно пересоздать, пользовательские результаты удалять нельзя.
Изменения подготовлены локально; публикация и развёртывание не выполнялись.
