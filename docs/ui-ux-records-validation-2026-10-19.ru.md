# Записи, граф и прошедшие события — 19 октября 2026

Реализовано в исходном React/Fastify приложении поверх предыдущего UI/UX рефакторинга.

## Интерфейс

- Главные разделы: Чат → Записи → Настройки. При запуске открыт чат. При входе в Записи выбраны Задачи; прежний переключатель с подвижной плашкой переключает Задачи / Заметки.
- В чате значок истории находится слева. Убраны видимые заголовки чата/истории, дубли настроек и уведомлений, действия названия/удаления текущего чата и пустая подпись истории. Скрытая подпись диалога сохранена для экранных дикторов.
- Календарь показывает сетку из 42 дней, переключение месяца, сегодняшний день и только задачи выбранного дня. Фильтры, категории и старые чекбоксы в этом виде скрыты. Новая задача получает выбранную календарную дату.
- Форма задачи содержит текст, категорию, приоритет и срок. Название берётся из первой непустой строки. Часовой пояс определяется автоматически; поля заголовка, меток и ключевых слов убраны.
- В Заметках добавлен граф: масштабирование, перетаскивание узлов и фона, поиск, полный список с подгрузкой, чтение заметки и переход к связанным заметкам. На телефоне открытая заметка прокручивается в видимую область; учитывается reduced motion.

## Сервер и Git

`GET /api/notes/graph` использует существующий GitSync и читает актуальные Markdown-файлы серверного vault. Связи строятся по wikilinks, Markdown-ссылкам и `related_note_ids`. Чтение документа защищено той же авторизацией и проверками путей, что остальные API. Приватные папки и настройки памяти исключены. Документ с ошибками YAML можно прочитать, не меняя файл.

Граф и тексты документов живут только в памяти React. API имеет `Cache-Control: no-store`; локальная копия vault, IndexedDB и файловый доступ в браузере не добавлены.

Новые задачи, обычные заметки, идеи, карточки людей, импортированные заметки и быстрая запись получают уникальный случайный код в заголовке: `Название #156G`. Выделение кода выполняется внутри сериализованной записи с проверкой кодов существующих файлов; редактирование сохраняет код, повтор запроса не создаёт запись заново. В именах файлов используется `Название - 156G.md`: это сохраняет код и не превращает `#` в якорь Obsidian. Длинные имена обрезаются с сохранением кода. Существующие пути автоматически не переименовываются.

## Выполненные задачи

- Отбор по `status: done` и `completedAt`: не раньше чем через 14 × 24 часа после завершения.
- Проверка каждый час независимо от расписания обычной сортировки. Большая очередь обрабатывается последовательно ограниченными пакетами.
- Используется существующий отдельный профиль сортировщика с проверкой его отделения от модели чата. Без настроенной модели исходники остаются на месте; состояние видно в Настройках.
- Модель получает исходные тексты как недоверенные данные и возвращает проверяемый JSON с итогом каждой задачи. Придуманные результаты запрещены инструкцией модели; качество фактов всё равно зависит от модели.
- Только после валидного ответа выполняется одна восстанавливаемая пакетная операция: сводки в `Past events/`, исходники в `Archive/Completed/`, перенос ссылок и создание `прошедшие события.base`, если его ещё нет. Существующая пользовательская база не перезаписывается.
- Исходные тела и метаданные сохраняются в архиве. Архивные записи исключаются из активных задач и списка редактируемых заметок. В графе архив остаётся доступен.
- Перед записью проверяются Git HEAD, хеши задач и право фонового исполнителя на запись. Изменение задачи, потеря lease или ошибка модели отменяют перенос. Пакетные записи наследуют журнал восстановления существующего VaultMutationService.

Формат файла базы сверён с [официальным синтаксисом Obsidian Bases](https://obsidian.md/help/bases/syntax): YAML с filters/properties/views и представлением table.
