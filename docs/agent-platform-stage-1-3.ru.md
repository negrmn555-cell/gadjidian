**Первые три этапа агентской среды: реализация и проверки**

Дата: 17 октября 2026 года. Выполнены исходные проверки и инструментирование, перенос суммаризации в фон, общий Markdown-парсер и индексированный поиск. Нумерация соответствует пунктам 1–3 пользовательского плана и этапам 0–2 в подробном документе.

**Что изменилось**

| Область | Реализация |
|---|---|
| Измерения | Длительности auth, очереди, контекста, провайдера, инструментов, поиска, мутаций и завершения; число LLM-вызовов, символы контекста, токены, RSS и задержка event loop |
| Приватность измерений | В метрики не включаются тексты, ключи и аргументы инструментов; фоновые работы отделены от контекста измерения пользовательского запроса |
| Суммаризация | Готовая память читается без вызова модели; старые сообщения обобщаются отдельными сохраняемыми заданиями, десять свежих реплик остаются дословно |
| Восстановление | Результат run и намерение обобщить историю сохраняются в одной ChatStore-транзакции; очередь восстанавливается после перезапуска; основной журнал согласуется с уже сохранённым ответом |
| Защита памяти | Generation после очистки, версии для CAS, хеши сообщений/источников, TTL по происхождению данных и проверка lease перед сохранением |
| Планировщик | Отдельный слот для summary и для остальных работ; очередь продолжает выполнение сразу после устаревшего задания, без ожидания следующего периодического тика |
| Исход запроса | Разделены completion и outcome success/failed/cancelled/partial; сохранённые результаты возвращаются при частичном сбое |
| Git | Чтение чата использует локальную ревизию; запись проверяет свежесть pull и версию файла; Git-команды имеют timeout |
| Markdown | remark/unified, GFM и math; единый YAML-parser, заголовки и позиции в исходнике; таблицы, код и формулы не делятся случайно |
| Поиск | Orama с русским стеммером, aliases, весами полей, точными путями, фильтрами, группировкой фрагментов по заметке и ссылкой на версию источника |
| Обновления | Локальные мутации, Git pull, управляемый сервером filesystem watcher и периодическая сверка; журнал изменений и контрольная ревизия в SQLite |
| Проекции | Изменяются только затронутые строки заметок/задач; неизменившийся снимок используется повторно; дубликаты ID диагностируются |
| Кеши | lru-cache с ограничениями размера, ключами версий и инвалидированием при изменениях; проверка доступа и доступности файла перед выдачей snippets |
| PWA | Экран памяти показывает фоновый пересчёт и получает новое состояние опросом; пользователь может продолжать разговор |
| Упаковка | В Dockerfile добавлено удаление dev-зависимостей после сборки; оценочные инструменты не нужны для работы сервера |

Общий поиск используется агентом, списком заметок, подбором связей, задачами и карточками людей. При индексации исходные Markdown-файлы не переписываются и ID автоматически не добавляются.

**Основные модули**

- `packages/core/src/frontmatter.ts`, `markdown-document.ts`: разбор источника без его перезаписи.
- `packages/core/src/search-index.ts`, `search.ts`: Orama, фрагменты, фильтры, кеши и актуализация.
- `packages/core/src/metrics.ts`: изолированные измерения запросов.
- `packages/server/src/summary-jobs.ts`, `chat-memory.ts`, `chat-store.ts`, `scheduler.ts`: фоновая память и восстановление.
- `packages/server/src/index-coordinator.ts`, `note-index.ts`: журнал изменений и инкрементальные проекции.
- `packages/server/src/sync.ts`, `vault-mutations.ts`, `request-ledger.ts`: свежесть, версии и исходы операций.

**Проверки**

Исходная версия прошла 21 core-тест и 79 серверных тестов. Итоговый набор: **26 core + 87 server = 113 тестов**, без ошибок. Проверка типов и сборка core/server/PWA проходят.

Добавлены проверки нарезки и исходных позиций, русского поиска, aliases/фильтров, отсутствия полного чтения файлов на прогретом поиске, изменения/удаления/переименования, ограничения доступа, фоновой памяти, очистки во время генерации, восстановления outbox, отдельного слота scheduler, конфликта после обновления источника и приватности метрик.

Реальный локальный HTTP-сценарий подтверждает: пользователь получает ответ до завершения медленной суммаризации; чтение памяти остаётся доступным; очистка истории запрещает сохранение запоздавшего резюме.

Для отката проверена совместимость четырёхколоночной записи `chat_memory` предыдущей версии. Номер версии памяти хранится в отдельной таблице, поэтому старый INSERT не ломается из-за новой колонки.

Promptfoo вызывает настоящий индекс приложения через собственный provider: **80/80 синтетических русских retrieval-сценариев**. Телеметрия CLI отключена; его данные направлены в игнорируемый `data/promptfoo`.

В отдельном каталоге выполнена чистая `npm ci --omit=dev --ignore-scripts`. Сервер запущен с этой установкой: прошли health, авторизованное создание заметки и поиск через API. Личный API-ключ не использовался. [Результат production smoke](production-install-smoke.json).

Проверка Mastra на локальном синтетическом OpenAI-compatible endpoint подтвердила текст, выполнение инструмента, stream API, отмену и обработку ошибки. assistant-ui импортируется с React 18.3.1. [Результат проверки совместимости](agent-compatibility.json).

**Измерения поиска**

Локальный стенд: Windows, Node 24.19.0. Корпус синтетический; модель и внешняя сеть в поисковых измерениях не участвуют. В p95 включены запросы к файловой системе для проверки доступности выбранных результатов, но не построение индекса.

| Корпус и реализация | p50 | p95 | Чтений содержимого за 80 прогретых запросов | Нужный источник в top-5 |
|---|---:|---:|---:|---:|
| 1 000 заметок, исходный поиск | 1 683 мс | 9 705 мс | 80 000 | 80/80 |
| 1 000 заметок, Orama | 1,1 мс | 9,3 мс | 0 | 80/80 |
| 10 000 заметок, Orama, heap 512 МБ | 1,1 мс | 183,6 мс | 0 | 80/80 |

Холодное построение: около 2,5 с на 1 000 и 27 с на 10 000 заметок. RSS большого прогона — около 428 МиБ; это отдельный benchmark-процесс, не полный сервер с OCR. Суммарный объём текста корпуса зависит от шаблона; измерение не следует представлять как проверку 100 МБ реальных пользовательских документов.

Это отдельные локальные прогоны Windows, чувствительные к дисковому кешу и фоновой нагрузке. Они подтверждают устранение полного чтения файлов на каждом запросе, но не измеряют сквозную скорость ответа внешней LLM.

Сырые обезличенные отчёты: [исходный поиск](search-benchmark-baseline.json), [Orama, 1 000](search-benchmark-indexed.json), [Orama, 10 000](search-benchmark-indexed-10000.json).

**Настройки и эксплуатация**

- `SYNC_FRESHNESS_MS=30000`: допустимый возраст последнего успешного pull перед новой записью.
- `GIT_TIMEOUT_MS=30000`: timeout Git-команды.
- `SYNC_PULL_INTERVAL`: период обновления local vault для чтения; принудительное обновление сохраняется.
- `GET /api/search/status`: авторизованная диагностика ревизии индекса и необработанных событий.
- `POST /api/chats/:id/memory`: ставит пересчёт в очередь; GET возвращает `refresh.state` queued/idle/failed.

Если remote недоступен и свежесть перед записью не подтверждена, новая запись отклоняется с `SYNC_UNAVAILABLE`. Уже созданный локальный commit сохраняется при сбое push; повтор публикации не повторяет пользовательскую операцию. Это различие покрыто Git-тестом.

Для выкладки нужна резервная копия обеих SQLite с учётом WAL, vault, настроек и ключей. Изменения схемы расширяющие. Сохранённые пользовательские файлы не откатываются автоматически вместе с бинарной версией. Журнал операций нельзя удалять для повторного запуска старого запроса.

**Ограничения и следующие работы**

Рабочий цикл пока использует прежний Agent; Mastra и assistant-ui подключены как dev-инструменты для проверки совместимости. Сквозной streaming, интерфейс ToolCall, постоянный Markdown-файл предпочтений, Langfuse, MCP и векторы относятся к следующим этапам.

Текущий защищённый provider transport буферизует SSE: stream API Mastra проверен, но текст до завершения HTTP-ответа в PWA ещё не передаётся. Это отражено в отчёте `transportStreaming: false`.

Индекс в RAM строится заново при старте. В SQLite сохраняются проекции, журнал изменений и версии checkpoint; загрузка дискового snapshot Orama не включена. Это сохраняет проверку источников после перезапуска, но оставляет стоимость холодного старта.

Аудит установленных рабочих зависимостей: нет high/critical, есть три low-записи в цепочке remark-math/KaTeX. Полный dev-аудит также содержит пять moderate и три high-записи, включая цепочку node-forge/JKS в Promptfoo. Оценочные библиотеки не используются серверным runtime; принудительный откат их API ради `audit fix --force` не применялся. Эти замечания остаются открытыми и не должны обозначаться как устранённые.

Метрики включены локально без внешнего экспортёра. Для объективного сравнения времени реальных LLM-ответов нужен отдельный прогон с выбранным провайдером и одинаковым набором запросов.
