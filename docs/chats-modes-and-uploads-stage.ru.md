# Третий этап: исправление интерфейса, чаты и режимы ИИ

Дата: 2026-10-02. Этот отчёт уточняет назначение элементов из второго этапа.

Это исторический отчёт. OCR, полный импорт, редактирование и память чата реализованы
в [четвёртом этапе](notes-import-memory-stage.ru.md); его описание заменяет ограничения ниже.

## Что изменено

- [x] Плюс открывает выбор фото/документов и загружает выбранные файлы на сервер.
- [x] Жёлтая кнопка выбирает «Задача / Заметка», показывает текущий режим и его описание.
- [x] Левое меню открывает историю чатов с кнопкой «Новый чат».
- [x] Настройки убраны справа сверху; доступны только из шторки истории.
- [x] Новый запуск, перезагрузка страницы или отдельная вкладка создают новый пустой чат.
  Повтор React-effect/HTTP-запроса при одном входе не создаёт второй чат.
- [x] Чат хранит свой режим, часовой пояс, историю, вложения и черновик уточнения.
  Выбор существующего чата не смешивает его контекст с новым.

Переключение чатов и режимов во время запроса блокируется в интерфейсе; сервер также
проверяет режим/версию. Результаты WebSocket сопоставляются с chatId/requestId.
Несохранённые текстовые черновики живут в текущей вкладке отдельно для каждого чата.
Невключённые в сообщение файлы после ухода из чата не выбираются автоматически.

## Следующий шаг: базовая работа режимов

**Задача.** Модель возвращает строгий JSON-черновик. Сервер отклоняет лишние поля,
дубликаты ключей, незавершённый JSON и вызовы инструментов. Срок проверяется сервером:
до даты включительно, до момента или именно в момент. Местное время преобразуется
в выбранном часовом поясе; невозможные даты и неоднозначное время DST вызывают уточнение.
Если срока нет, задача не записывается, сохраняется черновик и вопрос.
Ответ относится к draftId/draftVersion. Смена на заметку приостанавливает черновик;
возврат восстанавливает его, отмена удаляет только черновик.

Категория/приоритет определяются моделью по контексту, с резервными personal/medium.
Срок должен иметь буквальную цитату пользователя с признаком даты/времени.
Срок старой завершённой задачи не используется как срок новой. После проверки запись
идёт через TaskService и общий журнал Markdown/Git; повтор requestId не создаёт вторую задачу.
По ключевым словам сервер ищет связанные заметки и добавляет существующие wikilinks.
Выдуманные моделью relatedNoteIds не сохраняются.

**Заметка.** Палитра `/` содержит только `/quick`, `/idea`, `/person`, только в этом режиме.
Прямые quick/idea/person для текста не требуют модели. Свободный запрос работает через
ограниченные инструменты чтения/записи. Старые `/task`, сценарии и append_daily не могут
обойти новый режим задач. Дополнение управляемой задачи через NoteModeService запрещено.

Новые записи получают keywords, категорию, метки и существующие связи. Заметки/идеи
пишутся в Areas/{Study|Work|Personal}/{Notes|Ideas}, люди — в People. Вся старая база
автоматически не перестраивается. `/person Имя | информация` дополняет найденную карточку;
при тёзках спрашивает полный путь. Дополнение сохраняет старый YAML и текст.
Обновление отдельного факта с заменой прежнего значения пока не реализовано — новые
сведения дописываются. За один запрос допускается до восьми записей. При сбое модели
после записи ответ перечисляет уже сохранённые изменения.

## Контракты и API

Общие browser-safe типы: ChatSession, ChatPage, ChatSendInput, TaskDraftState, Attachment.

| Маршрут | Контракт |
| --- | --- |
| POST /api/chats | { entryId, timezone } → ChatSession |
| GET /api/chats | { items: ChatSession[] } |
| GET /api/chats/:id | ChatSession, только своему устройству |
| PATCH /api/chats/:id | { mode, expectedVersion } → ChatSession |
| DELETE /api/chats/:id/draft | { draftId, draftVersion } → ChatSession |
| POST /api/chat | ChatSendInput → ответ, actions, messageId, обновлённый chat |
| GET /api/messages?chat=ID&before=ID | страницы истории по 50 сообщений |
| DELETE /api/messages?chat=ID | очистка сообщений, файлов, запросов и черновика чата |
| POST /api/attachments?chatId=ID&name=NAME | application/octet-stream → Attachment |
| GET /api/attachments/:id/content?chatId=ID | авторизованная загрузка исходных байтов |

WebSocket message использует те же поля ChatSendInput. События содержат chatId/requestId;
cancel отменяет только соответствующий запрос. Все маршруты требуют app-key;
quick-key не подходит. Ключ устройства перепроверяется и для сообщений уже открытого WS.

История, сессии, draft, реестр запросов, исходные байты и извлечённый текст находятся
в отдельной *.chats.sqlite. Сессия истекает через 14 суток от создания, запрос/файл —
не позднее этой даты. Точная граница фильтруется при чтении, очистка работает при запуске
и раз в час. Старые сообщения импортируются в сессии повторяемо. Markdown/Git результат
не ограничен этим TTL. Эти SQLite-файлы и WAL/SHM исключаются из долгосрочных backup.

Идемпотентный реестр хранит hash входа и готовый ответ. Повтор с другим телом — 409.
После аварии незавершённый запрос не исполняется автоматически: возвращается просьба
проверить историю/результаты перед повтором. Автоматического восстановления незавершённых
диалоговых запусков пока нет; журнал уже подготовленных записей восстанавливается отдельно.

## Вложения и ограничения

Поддерживаются PNG/JPEG/WebP, TXT/MD/CSV/JSON в UTF-8, DOCX и PDF с текстовым слоем.
До пяти файлов в сообщении, до 5 МБ на файл, 50 МБ временных файлов на устройство.
Извлечённый текст — до 80 000 символов суммарно; изображения контекста — до 6 МБ суммарно.
Вложения прошлых реплик этого же чата доступны дальнейшим запросам (до пяти последних).
При превышении лимита сервер сообщает ошибку, а не обрезает документ молча.

PDF/DOCX извлекаются в ограниченном worker с таймаутом; ZIP не распаковывается на диск.
В DOCX читается основной текст, без полного сохранения таблиц, рисунков, колонтитулов.
PDF без текста возвращает явное сообщение о необходимости OCR. Изображения отправляются
только профилю с заявленной vision-поддержкой. SVG, HEIC, старые DOC/XLS и произвольные
архивы не поддерживаются. Имена файлов скрываются в HTTP-логах.

Это контекст разговора, **не полный перенос оригинала в Git/Obsidian**. Отдельная кнопка
полного переноса, durable assets, OCR, manifest и отчёт о полноте остаются следующим этапом.
Парсеры: [PDF.js Node example](https://github.com/mozilla/pdf.js/blob/master/examples/node/getinfo.mjs),
[fflate ZIP filter](https://github.com/101arrowz/fflate#unzipping).
