# Завершение плана мобильного приложения

Дата: 3 октября 2026 года. Этот отчёт заменяет списки «следующих этапов» в предыдущих отчётах. Реализация основных функций завершена; подключение реальных API, Git-сервера и push на телефоне — отдельная эксплуатационная проверка с настройками владельца.

По последнему уточнению пользователя SMS исключены: достаточно веб-уведомления. Реализованы общий журнал уведомлений в PWA и дополнительный браузерный Web Push по разрешению пользователя. Пять профилей ИИ чата и отдельный шестой профиль сортировщика сохранены.

## Новые контракты

Типы находятся в `packages/core/src/contracts.ts`. Секреты отсутствуют в публичных DTO.

| Контракт | Существенные поля / правила |
|---|---|
| `ChatSession` | `id`, `mode`, `timezone`, `version`, `expiresAt`, `pendingTask`, опциональный `providerId` |
| `TaskDraftState` | `id`, `version`, `createdAt`, `task`, опциональные `tasks`, `referenceInstant`, `question` |
| `Attachment` | `processing: queued/running/ready/failed`, `processingError`, сроки хранения и отчёт покрытия |
| `AutomationSettings` | Версия, дни/время/пояс, исключённые папки, бюджет пакета, настройки недельного чек-листа |
| `ScheduledJob` | Вид, dedupe key, scheduled time, settings version, состояние, attempt, lease и fencing token |
| `OrganizationPlan` | Input HEAD и hashes всех исходных файлов, policy/settings/provider versions, разрешённые patches, affected/deferred paths |
| `OrganizationPreview` | Полные before/after, перемещаемые пути, предупреждения и остаток очереди |
| `AppNotification` | `id`, `title`, `body`, `createdAt`, `read`; без SMS-номера или SMS-ключа |

Дополнительно к API предыдущих этапов:

- `GET/PUT /api/automation` — настройки и состояния фоновых заданий; PUT использует текущую версию.
- `POST /api/organizer/preview` — `{runId}`; `POST /api/organizer/apply` — `{planId, operationId}`.
- `POST /api/organizer/reconcile` — новая базовая точка после переписывания Git-истории.
- `POST /api/index/backfill` — `{operationId}`, ограниченный пакет старых заметок.
- `GET /api/tasks/legacy`, `POST /api/tasks/legacy/convert` — исходный путь/строка/hash и новая задача с обязательным сроком.
- `POST /api/attachments/queued` — бинарный поток, возвращает 202 и временное вложение; GET вложения возвращает актуальную обработку; POST retry повторяет только задание с ошибкой.
- `GET /api/notes/resolve` — разрешение wikilink с выбором при неоднозначности.
- `PATCH/DELETE /api/chats/:id` — название/режим или удаление истории по версии; `PUT .../provider` — отдельная привязка ИИ.
- `POST /api/ws-ticket` — короткоживущий одноразовый билет. Долговременный bearer больше не передаётся в URL WebSocket.
- `GET /api/chats/:id/runs` и `.../runs/:requestId` — восстановление состояния; POST cancel работает также при недоступном WebSocket.
- `GET /api/notifications`, POST read — постоянный в течение 30 дней чек-лист и отметка прочтения.
- `GET/POST/DELETE /api/notifications/push` — публичный VAPID key, подписка текущего устройства или отключение.
- `GET /api/sync/conflicts`, GET document, POST resolve/complete — просмотр base/ours/theirs, сохранение выбранного полного текста по hash, commit проверенного набора файлов.

## Проверенные ошибки и границы

- Без срока задача не записывается. Относительные «сегодня/завтра/послезавтра/через N дней» сверяются со временем соответствующей пользовательской реплики. Невозможные/двусмысленные времена DST требуют уточнения.
- Несколько задач валидируются до записи всего пакета. Недостающий срок сохраняет общий черновик. Старое уточнение завершённого draft отвергается.
- Повтор того же request/operation ID не вызывает второй ИИ и не создаёт второй результат. Несовпадающее тело даёт 409. После удаления истории возвращается 410 с путями уже сохранённых результатов; бессодержательный tombstone остаётся.
- Изменение заметки, HEAD, настроек или версии сортировщика после planning блокирует устаревший план. Приватные папки не доступны; изменение backlink в отдельно исключённой папке также блокирует перенос.
- Сортировщик добавляет metadata/связи, сохраняет тело и неизвестные YAML-свойства; не меняет задачи, служебные метки приоритета/категории, людей или факты произвольными инструментами.
- При переносе сохраняются aliases, anchors, block IDs, embeds и относительные Markdown-ссылки; примеры внутри кода не изменяются. Неоднозначная ссылка блокирует перенос.
- Чтение vault через приложение ждёт завершения пакета записи. Это не общая транзакция файловой системы для внешнего Obsidian; внешняя правка обнаруживается по hash и сохраняется при конфликте.
- Checkpoint содержит commit результата, подтверждённого публикацией; не подменяется последующим merge HEAD. Ошибка push оставляет восстанавливаемое задание и outbox.
- Перезапуск восстанавливает очередь OCR и разрешения Git. Потеря lease или смена настроек не разрешает старому обработчику новую запись/отправку.
- Чек-лист создаётся по свежему списку задач под координатором записи. Готовые/отменённые исключаются. Пустой список не создаёт уведомления. Опоздание более 30 минут или до момента после воскресной сортировки пропускает устаревший выпуск.
- Push accepted означает принятие шлюзом браузера, а не подтверждение чтения. Потерянный ответ получает unknown и автоматически повторно не отправляется. Чек-лист остаётся в приложении независимо от push.
- Отмена/истечение срока останавливает процесс OCR; лимиты ограничивают текст, страницы, распаковку, пиксели, время и очередь. Частичное распознавание явно отмечается; оригинал не теряется после импорта.
- Git merge сохраняет полный выбранный текст только при актуальном hash. Бинарные конфликты требуют ручного разрешения на сервере. Завершение слияния проверяет показанный список файлов и отсутствие unresolved paths.

Практические лимиты текущей версии: 5 МБ/файл, пять вложений сообщения, 50 МБ временных вложений и текста на устройство, восемь ожидающих распознаваний на устройство, 64 на сервер; один активный фоновой обработчик. Это лимиты реализации вместо предварительных чисел архитектурного эскиза. Для HEIC нужен внешний проверенный конвертер; неподдерживаемые форматы получают явную ошибку.

## Результаты проверки

- `npm run typecheck` — core, server, app.
- `npm test` — 100 тестов: 21 core и 79 server. Включены нативные протоколы, настоящее локальное bare Git-хранилище, публикация checkpoint, переписывание истории, настоящий конфликт Git, CAS, OCR на синтетическом изображении/смешанном PDF, TTL, повтор после очистки, fencing и одноразовый WebSocket билет.
- `npm run build` — готовая PWA и service worker с push handlers.
- После обновления Fastify/static и транзитивных зависимостей `npm audit` не сообщает уязвимостей.
- В браузере при 390×844 проверены новый чат, ручное создание/редактирование, календарь, смена статуса с перемещением в канбане, очередь → готовое вложение, меню истории и веб-уведомления. Открытие `/?notification=1` ведёт в журнал уведомлений и удаляет служебный query-параметр. После проверки размер окна возвращён к исходному. Скриншоты: `data/development-preview/screenshots/completion-calendar.png`, `completion-kanban.png`, `completion-tasks.png` (локальные игнорируемые артефакты).
- Исследование инвариантов через OpenCode CLI: `openai/gpt-6.1-sol`, high, plan; исходники/секреты/пользовательские заметки не передавались. Рекомендации сопоставлены с реализацией и тестами. Ревью исходников внешним OpenCode не выполнялось: автоматическая проверка разрешений ранее отклонила экспорт приватных файлов.

Реальные Anthropic/Gemini/OpenAI API, доставка push на телефон и Docker-образ на целевой Linux-машине здесь не проверялись. Для них нужны выбранные владельцем ключи, HTTPS, разрешение браузера и постоянный сервер. Это не замена выполненным локальным тестам протоколов и job logic.

## Запуск владельцем

1. Настроить постоянный сервер и `.env` по README; `SYNC_MODE=git`, `GIT_REMOTE`, `GIT_BRANCH`, HTTPS `PUBLIC_URL`. Локальный preview использует отдельный vault и `SYNC_MODE=none`.
2. Подключить телефон, добавить до пяти chat-профилей и отдельный organizer. Проверить выбранные возможности; canonical model сортировщика должен отличаться от основного.
3. При выключенном расписании сохранить пояс/папки/лимиты, просмотреть и применить первый план на копии vault. Затем включить среду/воскресенье. При изменении правил сначала выключить расписание и повторить пробный план.
4. Включить воскресный чек-лист. Он доступен через меню «Уведомления». Push включать только на нужных устройствах; разрешение остаётся выбором владельца.
5. Сделать защищённую резервную копию vault, основной SQLite и файла ключа. Не включать `*.chats.sqlite*`, OCR scratch, browser session drafts и обычную историю в долгосрочные backup.
6. Для ротации при файловом ключе остановить сервер, сохранить защищённую копию основной базы + ключа, выполнить `npm run cli -w @relay/server -- rotate-key`, запустить сервер и проверить профиль. Ротация сначала сохраняет key ring с прежним ключом, затем атомарно переупаковывает provider/VAPID/subscription записи в SQLite; прерванная ротация остаётся читаемой. ENV-ключ следует сначала перевести в управляемый файл вне vault.
7. После восстановления backup запускать один сервер-писатель. Recovery не перезапускает ИИ для уже принятых чатов. При Git-конфликте открыть настройки, сравнить версии, сохранить разрешения и проверить список commit слияния. Не применять reset/force-push к рабочему vault.
8. Проверить расписание на своём часовом поясе, push при закрытой установленной PWA и работу сервера при выключенном ПК. ОС/cgroup Docker ограничивает общий процесс и native OCR-память; контейнер не следует масштабировать на несколько писателей одного vault.

История ограничена 14 сутками, временные вложения и память не продлеваются бесконечно. Очистка внешних backup и журналов выбранного AI-провайдера контролируется владельцем этих систем. Постоянные результаты остаются в vault/Git независимо от удаления чата.
