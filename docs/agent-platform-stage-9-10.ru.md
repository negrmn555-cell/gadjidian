[подробного плана](agent-platform-implementation-plan.ru.md). По выбору пользователя
MCP даёт Codex и другим клиентам доступ к поиску и чтению заметок приложения.

## 9. Диагностика и проверка качества

Langfuse подключается явным экспортом OpenTelemetry HTTP/JSON. Автоматические
инструментации Mastra, SDK и HTTP не включены. Экспорт строится заново из разрешённых
полей: длительности стадий и первого текста, исход, вызовы модели/шаги, токены,
попадания/промахи поискового кеша, ожидающие изменения индекса, RSS, event-loop lag.
Интервалы стадий связаны с корневым запросом; ошибки стадий отмечаются отдельно.

Текст запроса/ответа и заметок, имена файлов, названия чатов, аргументы инструментов,
исключения и ключи не экспортируются. ID запроса, сессии, профиля и модели заменены
непрозрачными HMAC-ссылками с солью процесса. Имена моделей также не отправляются:
автоматическая денежная оценка Langfuse в этом режиме не заявляется. Токены видны
как счётчики запроса. Версии prompt/release явные; их нужно обновлять с правилами.
Токены отражают usage, полученный от API; отсутствие usage не означает нулевой
стоимости. В spans включены ожидание очереди мутаций и Git-синхронизация.

Очередь: 32 ожидающих записи плюс одна отправляемая, до 128 КБ на запись.
Возраст записи — до 30 с, отправка — до 3 с, без скрытых повторов. Shutdown даёт
до 1 с на flush, затем отменяет передачу. HTTPS/DNS проверяются существующим
транспортом; redirects не пересылают ключи. Outage не блокирует чат и не откатывает
записи. Пропуски и ошибки отправки видны в настройках.

Используется [поддерживаемый OTLP API Langfuse](https://langfuse.com/integrations/native/opentelemetry),
без устаревающего trace ingestion API.

### Включение

По умолчанию внешний экспорт выключен. Администратор задаёт в `.env`:

```dotenv
LANGFUSE_ENABLED=true
LANGFUSE_BASE_URL=https://cloud.langfuse.com
LANGFUSE_PUBLIC_KEY=ваш_публичный_ключ_проекта
LANGFUSE_SECRET_KEY=ваш_секретный_ключ_проекта
LANGFUSE_RETENTION_DAYS=14
```

Регион/свой сервер выбирается через base URL. Доверенный локальный приёмник
дополнительно разрешается точным origin в `LANGFUSE_ALLOWED_ORIGINS`.
**Фактический срок удаления нужно настроить в проекте Langfuse:** переменная лишь
фиксирует заявленную политику. Подробного режима с документами нет. Полный стек
self-hosted Langfuse на VPS не устанавливался.

Панель «Диагностика агента» показывает p50/p95, ошибки и состояние передачи.
Локальные показатели — последние 200 запросов с запуска, даже при выключенном
экспорте. Фоновые summary/index jobs не попадают в метрики активного запроса.

### Evals и измерения

Новый Promptfoo-адаптер вызывает настоящий вход чата, runtime, доменные сервисы,
SQLite и мутации на отдельном синтетическом vault. Детерминированная модель работает
через локальный HTTP. Проверяются поиск/раздел, приватный источник, partial после
записи, защита правил, явное запоминание, выдуманный и явный срок задачи. Каждый
случай проверяет replay без повторного модельного вызова.

[Отчёт качества](agent-quality-report.json): **80/80** поисковых и **14/14** агентских
случаев, по семь для Mastra/legacy. Платной модели и LLM-grading нет. Это проверка
маршрутов и инвариантов, а не оценка ответов настоящей модели на учебных материалах.

[Локальное сравнение](agent-diagnostics-benchmark.json), по 20 прогретых запросов
с искусственной задержкой модели 10 мс:

| Режим | p50 ответа | p95 ответа | Пиковый RSS |
|---|---:|---:|---:|
| Экспорт выключен | 44,77 мс | 47,09 мс | 275,0 МиБ |
| Экспорт включён | 56,20 мс | 61,03 мс | 300,0 МиБ |

Ошибок/пропусков нет. В этом прогоне экспорт добавил около 14 мс к p95 полного
ответа. Он не ждёт ответа приёмника, но подготовка метаданных и отправка имеют
накладные расходы. Режимы идут последовательно в одном процессе, поэтому это
наблюдение требует повторения на целевом сервере; RSS может включать удержанную
память предыдущего режима. Это не проверка мощности VPS и не доказательство
ускорения модели.

```powershell
npm run eval:retrieval -- --output data/retrieval-evals.json
npm run eval:agent -- --output data/agent-evals.json
node evals/report.mjs
node benchmarks/agent-diagnostics.mjs
```

## 10. MCP для внешних клиентов

Endpoint `/mcp` работает внутри Fastify, со стабильным production SDK
`@modelcontextprotocol/sdk` **1.32.1**. Транспорт — stateless Streamable HTTP с JSON,
без отдельного сервера и сохраняемых SSE-сессий.
[Официальная документация SDK](https://ts.sdk.modelcontextprotocol.io/server).

| Инструмент | Назначение |
|---|---|
| `search_notes` | Тот же Orama-поиск, до десяти результатов |
| `read_note` | Точный относительный `.md`-путь, хеш и признак сокращения |
| `read_section` | Раздел по path/chunkId из поиска |

Определения и выполнение переиспользуют внутренние ToolSpec/core. Результат
ограничен 16 000 символов, полное чтение заметки — существующими 12 000. Длинные
заметки читаются по разделам. Приватные/игнорируемые пути, symlink, выход из vault
и файл предпочтений запрещены. Для MCP отключён fallback с пути на похожее название.
Ошибки скрывают абсолютные серверные пути. Результаты помечены как данные источника.
Запись, задачи, настройки, секреты, временные вложения и история не выставлены.
Произвольные внешние URL и model sampling не принимаются.

### Подключение клиента

1. В настройках открыть «Поиск и чтение через MCP» и создать ключ клиента.
2. В MCP-клиенте выбрать HTTP/Streamable HTTP, указать показанный URL и заголовок
   `Authorization: Bearer <MCP-ключ>`.
3. Выполнить `search_notes`, затем `read_note` или `read_section` по найденному пути.

Ключ показывается один раз, без localStorage/sessionStorage. В SQLite хранится
SHA-256 токена с высокой энтропией. Ключи видны и отзываются только выдавшим
устройством; его отключение закрывает доступ всем его клиентам. Срок — 1–90 дней
(в UI 7/30/90), до десяти активных ключей устройства и 128 всего.

App/quick-ключ не принимается MCP, MCP-ключ не подходит для остального API.
Токен передаётся только в Authorization. Host/Origin проверяются относительно
`PUBLIC_URL`; TLS обеспечивает существующий reverse proxy. OAuth/discovery для
клиентов без явного Bearer-ключа пока не добавлены.

Конкуренция — восемь запросов всего / два на устройство, вход до 128 КиБ,
чтение до 10 с, HTTP до 12 с. Ключ проверяется повторно перед результатом:
отзыв во время чтения подавляет поздний ответ. Отмена клиента закрывает запрос.
Само файловое чтение может доработать без мутаций; результат отбрасывается.
Отключение endpoint: `MCP_ENABLED=false`. Внутренние инструменты продолжают
вызываться напрямую, без обхода через MCP.

## Проверки и границы выпуска

- **166 тестов: 38 core + 128 server**, проверка типов и сборка трёх пакетов.
- Реальный MCP SDK-клиент по HTTP: initialize, инструменты, русский поиск,
  заметка/раздел, запреты, отзыв/истечение, изоляция устройств, Host/Origin,
  отмена и отзыв во время чтения.
- Локальный OTLP HTTP-приёмник: формат, parented spans, обезличивание вложенных
  secrets/errors, очередь, outage, shutdown и чат при заблокированном приёмнике.
- Исправлена редкая ошибка чтения ключа шифрования: бинарный ключ длиной 32 байта
  с первым байтом `{` больше не принимается за JSON key ring. Регрессионный тест
  проверяет повторное открытие и расшифровку без замены файла ключа.
- [Браузер](agent-integrations-ui.json): выдача/скрытие/отзыв ключа, MCP-запрос с UI
  ключом, отсутствие его в хранилищах браузера, диагностика, 320/390/1440 px,
  без JS-ошибок и переполнения.
- [Production smoke](production-runtime-smoke.json): отдельная установка без
  dev-зависимостей, MCP-клиент и диагностика вместе с прежними сценариями.

UI: `node benchmarks/agent-integrations-ui.mjs`; необязательный первый аргумент —
каталог node_modules с Playwright. Используются изолированный браузер и синтетический
vault; скриншоты находятся в игнорируемом `data/agent-integrations-screens/`.

Код подготовлен локально. Облачный аккаунт Langfuse, установленная конфигурация
Codex, платная модель, Docker и VPS не подключались. Протокол проверен настоящим
SDK-клиентом, а не только импортом библиотеки. Для облачного Langfuse нужны ключи и
retention проекта; для внешнего MCP-клиента — URL обновлённого сервера и свой ключ.

Миграция 8 добавляет таблицу MCP-ключей. При откате сохраняются обе SQLite и vault.
Отключение интеграций не удаляет пользовательские результаты. Публикация и
развёртывание не выполнялись.
