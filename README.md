# Obsidian Relay

Ваше хранилище Obsidian — с телефона, из браузера, **даже когда компьютер выключен**.

Отличие от Elton AI: сервер здесь не «почтальон», а отвечающий. Он держит копию хранилища (через git),
сам ищет и читает заметки, создаёт новые и вызывает модель. ПК с Obsidian — лишь ещё один участник
синхронизации: включён — изменения разъезжаются за минуту; выключен — сервер работает один.

```
Телефон (PWA) ──HTTPS/WSS──► Сервер (VPS, Docker)
                              ├─ Fastify: код → ключ устройства, чат (WebSocket), REST
                              ├─ Агент: search/read/create + OpenAI-совместимая модель
                              └─ /data/vault ◄── git pull/push ──► git-remote ◄── obsidian-git ── ПК
```

Что умеет: записать мысль, добавить строку в ежедневную заметку, ответить по заметкам,
показать заметку, режимы «Задача / Заметка», команды /quick, /idea, /person, кнопка быстрой записи с локскрина,
несколько устройств с отзывом. В новой области «Задачи» доступны ручное создание задачи
с обязательным сроком, категория и приоритет, фильтры, сортировка и изменение статуса.
Голосовой ввод и транскрибация удалены.
Настройки позволяют добавить до пяти ИИ для чата и отдельный профиль сортировщика.
Интерфейс обновлён по мобильному референсу.
Выбор основного ИИ выполняется в настройках. Боковое меню теперь открывает историю чатов
и новый чат; настройки доступны внутри него. Новый вход открывает пустой чат.
Из области задач можно создавать и редактировать заметки и карточки людей.
Фото и сканы распознаются локально на русском и английском; полный импорт сохраняет
текст, оригинал и отчёт обработки в Obsidian/Git. Память чата содержит краткое резюме
и проверяет изменения исходных заметок; она удаляется вместе с историей через 14 дней.

Честная цена: **нет сквозного шифрования** — сервер видит заметки, иначе он не смог бы отвечать без ПК.
Личные папки (`Private/`, `Journal/`…) исключаются из git и никогда не покидают ПК.

## Структура

```
packages/core     ядро: адаптер хранилища поверх ФС, поиск, шаблоны, инструменты, агент, команды
packages/server   Fastify + WebSocket + SQLite (node:sqlite), git-синхронизация, CLI
packages/app      PWA (React + Vite + vite-plugin-pwa)
deploy/           Dockerfile, docker-compose (Caddy + relay), пример .gitignore для хранилища
```

## 1. Хранилище → git

1. На ПК в корне хранилища сделайте git-репозиторий и добавьте `.gitignore` (пример: `deploy/vault.gitignore.example`).
   Личные папки перечислите там же — они не попадут на сервер.
2. Создайте **приватный** репозиторий (GitHub/GitLab/Gitea или голый репо на самом VPS) и запушьте.
3. В Obsidian поставьте плагин **Git** (obsidian-git). Настройки: auto commit-and-sync каждые 5–10 минут,
   auto pull при открытии, «Pull updates on startup». Всё — теперь ПК сам коммитит и тянет.

## 2. Сервер (VPS)

Нужны: Ubuntu с Docker, домен, указывающий на VPS, ключ OpenRouter/OpenAI (или Ollama на VPS).

```bash
git clone <этот репозиторий> obsidian-relay && cd obsidian-relay
cp .env.example .env            # заполните DOMAIN, PUBLIC_URL, LLM_*, GIT_REMOTE, VAULT_*
mkdir -p deploy/ssh && ssh-keygen -t ed25519 -f deploy/ssh/id_ed25519 -N ""
cat deploy/ssh/id_ed25519.pub   # добавьте как Deploy key с правом записи в репо хранилища
ssh-keyscan github.com > deploy/ssh/known_hosts
cd deploy && docker compose up -d --build
docker compose logs -f relay    # в логе появится первый код подключения
```

Сервер сам склонирует хранилище в `/data/vault`, тянет изменения раз в `SYNC_PULL_INTERVAL` секунд
и перед каждым ответом, а после записи с телефона коммитит и пушит.

Управление:

```bash
docker compose exec relay node packages/server/dist/cli.js code        # новый код подключения
docker compose exec relay node packages/server/dist/cli.js devices     # устройства
docker compose exec relay node packages/server/dist/cli.js revoke 3    # отключить
docker compose exec relay node packages/server/dist/cli.js reset       # отключить все
docker compose exec relay node packages/server/dist/cli.js quick-key   # ключ для кнопки
```

## 3. Телефон

1. Откройте `https://<DOMAIN>` в браузере телефона и **добавьте на домашний экран**
   (iPhone: Поделиться → «На экран Домой»; Android: меню → «Установить приложение»).
   Из обычной вкладки вход закрыт — как в оригинале (`REQUIRE_STANDALONE=false` отключает это для разработки).
2. Откройте с иконки, введите код подключения. Код одноразовый: телефон получает свой ключ.
3. В настройках добавьте ИИ: название, протокол OpenAI-compatible / Anthropic / Gemini,
   адрес API, точный ID модели и ключ.
   «Проверить подключение» делает небольшой служебный запрос; он может расходовать лимит API.
   Сохранённый ключ не отображается. Пять профилей предназначены для чата, шестой — для сортировщика.
4. Жёлтая кнопка выбирает «Задача / Заметка». В режиме задачи ИИ уточняет отсутствующий срок;
   в заметке `/` открывает три команды. Плюс загружает фото/документы для контекста разговора.
   Переключатель сверху меняет область, боковое меню открывает историю и новый чат.
   Настройки внутри меню → провайдеры, расписания, уведомления, Git-конфликты, устройства,
   код и ключ быстрой записи. Для сортировки сначала просмотрите план и примените его;
   после этого можно включить расписание. Недельный чек-лист доступен в журнале приложения;
   Web Push включается отдельно на каждом устройстве с разрешения браузера.

### Кнопка быстрой записи (iOS Команды / Android HTTP Shortcuts)

Создайте ключ в Настройках (или `cli quick-key`). Запрос:
`POST https://<DOMAIN>/api/send`, заголовок `content-type: application/json`,
тело `{"token": "<ключ>", "text": "<текст>", "chat": "quick"}` (`"chat": "daily"` — строкой в сегодняшний день).
Ключ умеет только создавать заметку; код подключения в нём не работает.

На Android приложение само появляется в меню «Поделиться» (share target).

## Локальная разработка

```bash
npm install
npm run build
npm test                                  # тесты core и server, включая Git и миграции
# .env в корне: VAULT_PATH=<путь к копии хранилища>, LLM_*, SYNC_MODE=none, REQUIRE_STANDALONE=false
npm run dev:server                        # http://localhost:8080 (отдаёт собранную PWA)
npm run dev:app                           # vite на :5173 с прокси /api
```

Требуется Node 22.13+ (используется встроенный `node:sqlite` без флагов). Для `SYNC_MODE=git` нужен `git` в PATH.

После изменения серверного кода пересобирайте и перезапускайте сервер. При обновлении PWA
публикуйте полностью собранный `dist`, чтобы HTML и ресурсы относились к одной версии.

### Ключи ИИ-провайдеров

Сервер шифрует API-ключи в SQLite. Сохраните `DATA_DIR/secrets/provider-master.key`
(или настроенный `PROVIDER_MASTER_KEY`) отдельно от базы в защищённой резервной копии.
При потере ключа существующие секреты недоступны; сервер не создаст замену автоматически.
`PROVIDER_KEY_FILE` должен находиться вне vault и Git. Для ротации остановите сервер,
сделайте защищённую резервную копию базы и ключа, выполните
`node packages/server/dist/cli.js rotate-key`, сохраните новый ключ и запустите сервер.
Команда поддерживает файловый ключ; для `PROVIDER_MASTER_KEY` она возвращает явную ошибку.

Параметры `LLM_*` однократно импортируются в первый профиль; дальнейшие изменения выполняйте
через приложение. По умолчанию доступны публичные HTTPS API. Для локального Ollama укажите
точный origin в серверном `PROVIDER_ALLOWED_ORIGINS`, например `http://127.0.0.1:11434`.
Сортировщик использует отдельную модель, отличную от основной модели чата. Расписание по
умолчанию — среда и воскресенье 23:59; недельный веб-чек-лист — воскресенье 23:50.
Обе функции изначально выключены и настраиваются в приложении. SMS исключены по уточнению пользователя.

### Хранение задач и истории

Новые задачи — отдельные Markdown-файлы с YAML-свойствами в
`Areas/{Study|Work|Personal}/Tasks/`. При ручном редактировании в Obsidian сохраняйте `id`,
`relay_schema`, `type` и обязательные свойства срока. Старые чекбоксы в ежедневных заметках
не преобразуются автоматически: в области задач их можно просмотреть и преобразовать,
указав обязательный срок. Исходная строка сохраняется со ссылкой на созданную задачу.

Запись проходит через журнал операций: повтор одного `operationId` не создаёт вторую задачу,
а изменение устаревшей версии возвращает конфликт. При включённом Git сервер создаёт
локальный коммит перед подтверждением записи; успешный push отмечается отдельно.
Неудачный Git push повторяется с увеличением интервала. Git-конфликты разрешаются вручную
через редактор в настройках с проверкой версии; завершение merge требует явного подтверждения.

При запуске существующая SQLite-база автоматически получает миграции. История сообщений
переносится в отдельный файл `<имя базы>.chats.sqlite`. Сообщения старше 14 суток не выдаются
API; очистка выполняется при запуске и каждый час. Заметки и задачи этим сроком не ограничены.
Исключайте `*.chats.sqlite`, их `-wal` и `-shm` из долгосрочных резервных копий. Копии старой
базы, сделанные до миграции, могут содержать историю дольше 14 дней; миграция их не удаляет.

## Настройка агента

`data/scenarios.json` (путь — `SCENARIOS_FILE`):

```json
{
  "systemPrompt": "Пиши коротко. Ссылки на заметки оформляй как [[wikilinks]].",
  "scenarios": {
    "план": "Прочитай сегодняшнюю заметку и составь план дня из 3 пунктов.",
    "ретро": "По ежедневным заметкам за неделю напиши ретроспективу: что получилось, что нет, что менять."
  }
}
```

systemPrompt дополняет режим заметки. Пользовательские slash-сценарии в новом интерфейсе
пока отключены: команды ограничены /quick, /idea, /person, а режим задач пишет только через TaskService.
